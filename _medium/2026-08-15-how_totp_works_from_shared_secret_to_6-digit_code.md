Most of us use one-time passwords every day, but the mechanism behind them is surprisingly elegant.For TOTP (Time-based One-Time Password), the authenticator app and the server first share the same secret key.When generating a code, both sides independently calculate: counter = current Unix time / 30 secondsThis means the same 30-second window produces the same counter. That counter is then passed into a hash function, commonly HMAC-SHA1: HMAC(secret, counter)The hash function processes the input in fixed-size blocks, repeatedly updating its internal state until it produces a fixed-length digest. For SHA-1, that digest is 160 bits. The result is still far too long for a human to type, so TOTP applies dynamic truncation to extract a 31-bit integer, then reduces it to six digits: OTP = value % 1,000,000The final result looks like: 759234The server verifies the code by performing the exact same calculation using its copy of the shared secret and the current time window.So the full flow is:Shared Secret + Current Time → time counter → HMAC → fixed-length digest → truncation → modulo 1,000,000 → 6-digit OTPThe interesting part is that the authenticator and server do not need to send the OTP to each other. They arrive at the same value independently because they share the same secret, time window, and algorithm.In practice, one of the bigger limitations of a six-digit OTP is simply its small search space: there are only one million possible codes.
